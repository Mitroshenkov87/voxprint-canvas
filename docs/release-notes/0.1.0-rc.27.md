VOXPrint AI Canvas 0.1.0-rc.27, build 26.

Fixed:

- The first frame of a Photoshoot series died in the VAE after sampling, and the series wrote no pictures. The latents are now on the same device and the same dtype as the VAE immediately before decode. On a CUDA machine the VAE decodes in BF16.
- A long stage writes a heartbeat line to voxprint.log, including when Canvas is started with pythonw and when the log file is briefly locked.
- The text encoder was opened from disk more than once in one series, and the scenario writer's weight hash was computed again on every open. Each model is loaded once. The hash and the FP8 cast are reused.
- Heavy models are read from disk once per session into system RAM (voxprint-common 0.4.2 `model_park`), already cast. A stage copies the model it needs from RAM to VRAM and drops that VRAM copy when the stage ends. A 96 GB machine keeps every model. A 64 GB machine keeps what fits, in order: transformer, text encoder, VAE, writer, then the checks. A 32 GB machine reads from disk when a stage needs a model.
- A check that finished on the GPU is parked before the writer and before the picture, including when its device flag says CPU. The picture is accepted when free VRAM fits the FP8 transformer and the VAE after that park. The first SSD read of each model is logged on its own.
- The VAE decodes with ``tiled_decode`` on the instance that holds the weights. A 1024 frame used to ignore the tiling flag, because the stock tile is the whole frame. Pixels are scaled with ``(x / 2 + 0.5).clamp(0, 1)``, synchronized, and copied to CPU float32. The VAE stays plain BF16, with no FP8 casting hook. `--version` prints `0.1.0-rc.27 build 26`.
- Encode and decode both unpark the VAE, require CUDA BF16, and park it again when the call returns. The second frame's img2img encode was still using the CPU copy. Other models are parked before the VAE runs, and each stage logs its own allocation peak.
- The output check parks its models before the frame is saved. A check that already lives in RAM is unparked from that copy, and the picture check's label embeddings are computed once per device.
- Sampling, encode, and decode run with autograd off, and the VAE weights do not require grad. Decode blends one tile at a time into a CPU buffer, then returns the reserved GPU memory. The log records ``grad_enabled`` at decode. The output check records load, the device query, image prepare, and the cache release on their own lines.

Install the Windows setup, or unpack the Linux archive and run `./install.sh`. The download does not include the GPU libraries or the model files. Those are fetched on the PC. HEIC still needs a system codec.
