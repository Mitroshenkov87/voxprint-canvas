VOXPrint AI Canvas 0.1.0-rc.28, build 27.

Fixed:

- The scenario writer on a 16 GB card was kernel-launch bound. Decode keeps a StaticCache for the prompt plus the new tokens and replays one CUDA graph for each greedy token. Prefill stays eager. The graph is captured again when the weights move after unpark. If capture fails, decode stays eager and the log records `graph=eager` with the reason. The writer does not install an FP8 or torchao matmul. It loads with `from_pretrained(view, dtype=bfloat16, device_map="cuda")`, straight onto the GPU, as in the Proving Ground bench. The writer and every picture check build their models under one process lock: transformers sets torch's process-wide default dtype while it builds a model, and a check loading as fp32 on the side thread had turned part of the writer fp32 (13.1 GB). The loaded dtype is logged, and any fp32 parameter left is cast to bf16 one tensor at a time. A meta or fp32 weight is still refused before park. Closing the writer drops the CUDA graph, its StaticCache and static buffers, moves any tensor still on CUDA to RAM, empties the allocator, and logs the residual with `stage writer release`. More than 0.5 GB is logged as `writer.residual`. The reserved peak is cleared before the 14 GB check. The decode clock calls `torch.cuda.synchronize` before it is read, and `tokens` is the number of ids actually produced. After a park, unpark moves every parameter and buffer back to CUDA and the static cache is captured again. A tensor left on CPU or meta stops the writer. The writer does not decode on CPU while CUDA is available. The log line carries `prefill_ms`, `decode_tok_s`, and `graph=captured` or `graph=eager`. Proving Ground measured 49.4 tokens per second at 7.75 GB, token-identical to plain bf16.
- A Photoshoot series runs in three phases instead of loading and unloading models for each frame. Prep opens the writer once for every scenario chunk, then encodes every frame prompt with the text encoder alone and keeps the embeddings in RAM. Prep then frees the card and stops with `vram.residual` when more than 0.5 GB is still allocated. Render loads the picture model once and samples every frame while it stays on the GPU. A series that follows its first frame draws that frame whole first. Decode turns every kept latent into pixels in one VAE session. Each phase logs `stage phase <name>` with its own CUDA peak, and each frame logs `stage frame render` and `stage frame decode` with its time. The text encoder, the transformer, and the VAE now build under the same process lock as the writer, and the text encoder logs its loaded dtype.
- A person series no longer puts a made-up look (ethnicity, hair, eyes, face, build picked from the seed) in front of the prompt. That look overrode the prompt: a prompt asking for blonde hair came back with black hair on every frame. The prompt's own words now lead every frame.
- `--places different` now shows in the pictures. A different-place series no longer redraws each frame from the first frame's pixels, so each frame follows its own place, pose and light. A same-place person series still follows its first frame. Planned shots change the light on every frame.
- After decode, the models that run before a frame is written are placed once for the whole series instead of once per frame. Frames are written after that pass.
- A scenario reply is shorter. Each shot is one compact line, and the new-token cap follows the frame count (48 tokens a frame, still capped at 8192). The subject is still described, appearance first.
- Picture-check weights are read from disk into RAM on a side thread while the writer and the sampler run. The checks themselves, their thresholds, their order, and the fail-closed stop are unchanged. Nothing is saved until the output check passes.
- Photoshoot can hand Forge a PNG (the default), JPEG, WebP, or AVIF. `--export-format` and the Export setting choose it. A single picture still defaults to AVIF.
- Every frame was coming back as a collage. Series wording in the shared subject ("every frame", "varied shots and angles", and the same family of words) was copied into each frame prompt. A frame prompt is now that frame's appearance plus its own pose, camera, scene, and place, with those series words removed. The collage-line filter still drops a shot that describes several views. Prompt embeddings are one vector per frame. The log records `chars` and `sha` for that prompt, not the words.
- A model is opened only from its MDL view (hard links into the blob store). A plain copy in `models/<org>--<name>` is ignored and is not deleted. A download is queued with MDL. An incomplete view says "Model missing, fetch it with MDL." The log records `kind=view` for each resolved model.
- Setup pins voxprint-common 0.5.1 (sha256 `c618239aa2f966608aea17ec108df2d9ed9c4bdc7edd81ef3e6a3fa960ee3939`). Before any download, the installer runs `voxprint-mdl adopt --app canvas --from <legacy dir>` once per legacy folder. There is no Canvas adopt fallback. A non-zero adopt is logged as `model adopt id=… action=failed` and that model is left out of the download. The legacy folder stays on disk. Preflight then fails with `reason=view`.
- Before a heavy load, preflight checks that every picture model and every gate model has a complete view, that at least 1 GiB of disk is free, and that the machine has at least 12 GiB of RAM. A legacy folder that is still incomplete is not queued for download. Those checks stop after 5 seconds. It writes one `preflight ok` or `preflight fail reason=...` line and does not load a model when it fails.
- A parenthesized outfit, lighting, or location list is no longer copied into every photograph. Each shot keeps one item from each list, chosen from the seed, and the shots cover the list. A long subject keeps that shot's outfit, light, and place when the encoder cap would otherwise cut them off. Stripping "every frame" from "same woman in every frame" leaves "same woman". `different` / `various` phrases are removed. The words frame, border, photo shoot, photoshoot, panel, sheet, and series (and their plurals) are stripped; `frame` is written as `shot`, and the lead stays `A single photograph of`.
- The fixed test character is `an Asian woman, about 30, blonde, athletic with defined muscles`. When the idea contains that sentence, every frame prompt copies it verbatim.
- The writer weights are fetched from the Hugging Face mirror `Mitroshenkov87/voxprint-mirror-huihui-qwen3-4b-instruct-2507-abliterated` at commit `2c219b659d064d24236fd748c19cc2e579cbe3be`, then from upstream `huihui-ai` at `c9bd464550d4078c72af0dd22aa18d0437868ce3`. The twelve pinned file hashes match the catalog and are unchanged.

Install the Windows setup, or unpack the Linux archive and run `./install.sh`. The download does not include the GPU libraries or the model files. Those are fetched on the PC. HEIC still needs a system codec.
