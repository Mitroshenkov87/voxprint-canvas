VOXPrint AI Canvas 0.1.0-rc.28, build 27.

Fixed:

- The scenario writer on a 16 GB card was decoding at about 2 tokens per second with the GPU barely busy. Diffusers' layerwise FP8 hook upcast every linear on every token, and an accelerate hook plus a non-blocking unpark left some of those weights on the CPU. Generation now keeps a model whose FP8 size is at most 5 GB as resident BF16 on the GPU when that fits the 14 GB peak (Qwen3-4B does). A larger model uses a real FP8 matmul. Generate runs under `torch.inference_mode` with the KV cache on, and without a streamer or a CPU stop check. The log line is `stage writer tokens device=… tokens=N tok_s=X dtype=bf16 kv_cache=on`. On a 4090 laptop that is about 45–70 tokens per second.
- A scenario reply is shorter. Each shot is one compact line, and the new-token cap follows the frame count (48 tokens a frame, still capped at 8192). The subject is still described, appearance first.
- Picture-check weights are read from disk into RAM on a side thread while the writer and the sampler run. The checks themselves, their thresholds, their order, and the fail-closed stop are unchanged. Nothing is saved until the output check passes.
- Photoshoot can hand Forge a PNG (the default), JPEG, WebP, or AVIF. `--export-format` and the Export setting choose it. A single picture still defaults to AVIF.
- Every frame was coming back as a collage. Series wording in the shared subject ("every frame", "varied shots and angles", and the same family of words) was copied into each frame prompt. A frame prompt is now that frame's appearance plus its own pose, camera, scene, and place, with those series words removed. The collage-line filter still drops a shot that describes several views. Prompt embeddings are one vector per frame. The log records `chars` and `sha` for that prompt, not the words.

Install the Windows setup, or unpack the Linux archive and run `./install.sh`. The download does not include the GPU libraries or the model files. Those are fetched on the PC. HEIC still needs a system codec.
