# 0.1.0-rc.36

## Fixes

- A valid Forge LoRA applies again. rc.35 loaded it with the diffusers default key prefix `transformer`, which matched no key in a Forge export, so the LoRA was rejected. rc.34 had the same problem but did not report it, so the LoRA was silently left out. The adapter now loads its keys as they are in the file.
- A LoRA whose matrices do not fit the model stops with `lora.invalid` and exit 2. The check runs before any model loads. The whole batch then ends at once instead of reloading the model for every row and exiting 1 with "No shot was kept."
- Two ram96 jobs at once no longer fill RAM. Each job picks its RAM tier when it starts. It counts the text encoder, transformer and VAE plus a reserve against free RAM, minus what other Canvas jobs still expect to use, as listed in a shared RAM ledger in the temp folder. When there is not enough room, the job keeps fewer models (ram64) or reads them from disk (ram32). Free RAM is also checked again before each park.

## Unchanged

- A job on its own keeps the tier it was set to.
