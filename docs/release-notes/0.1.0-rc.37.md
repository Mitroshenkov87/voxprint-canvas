# 0.1.0-rc.37

## Changes

- WebP is the default file type. Pictures save as lossy WebP (quality 90), which stays a setting. Photoshoot series and the Forge hand-off save lossless WebP. PNG, JPEG and AVIF stay options; nothing forces PNG.
- The series contact sheet (`overview.*`) and `series.zip` work with any frame type, not only PNG.
- How a picture was made (prompt, seed, steps, base model, LoRA name, strength and SHA-256) is written into WebP, AVIF and JPEG as XMP, with an EXIF copy, and into PNG as UTF-8 text chunks. JPEG XL is written without it, because the encoder takes no metadata. "Save metadata" stays on by default.
- voxprint-common 0.6.1. After a CUDA fault the worker sends its reply and exits with code 75 through `reply_and_exit`. The host restarts it as planned: the job counts as finished and no crash bar is shown.
- A MOSS LoRA's base tag is `moss5b`. The user-facing values `moss` and `moss-image` still select it, and so do the older tags `moss-image-sft` and `moss-image-base`. The Z-Image tag is unchanged (`z-image` still means Z-Image-Turbo). The LoRA runs on the `moss-image-sft` catalog base.
- A LoRA file's `voxprint.lora.base_variant` (expected `moss-image-sft`) and `voxprint.lora.base_sha256` (or `base_sha256`) are kept on the LoRA entry. A `moss5b` LoRA whose variant is `moss-image-base` still loads. The warning is logged and listed under `warnings` in `--json`.
- The 16 GB compact MOSS row is now `voxprint-moss-image-sft-compact`. The previous id was `moss-image-sft-compact-16gb`. Its quant note is `(fp8/int8/nf4, chosen by moss-prequant)`. Hashes stay pending.

## Unchanged

- The content gate. A LoRA for a base Canvas cannot run still asks for a retrain. The UI apart from the default file type.
