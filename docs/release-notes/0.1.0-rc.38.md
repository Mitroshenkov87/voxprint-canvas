# 0.1.0-rc.38

## Changes

- Picture metadata is off by default. Turn it on with the `canvas.save_metadata` setting, the `VOXPRINT_CANVAS_SAVE_METADATA` environment variable, or `--save-metadata` on the CLI. When on, it is written as in rc.37 (XMP+EXIF in WebP, AVIF and JPEG; iTXt in PNG).
- MOSS-Image-SFT is the default generator. Z-Image stays available as an option. The 16 GB compact build row `voxprint-moss-image-sft-compact` (fp8/int8/nf4, chosen by moss-prequant) is listed; its repo, revision and SHA-256 are still pending, so a fresh 16 GB install has no default model download yet.
- LoRAs are routed by base tag. A MOSS LoRA's base tag is `moss5b`; the user-facing values `moss` and `moss-image`, and the older tags `moss-image-sft` and `moss-image-base`, still select it. A LoRA whose base Canvas cannot run fails with `lora.retrain` (CLI exit 2, `retrain` field in `--json`) and offers a Forge retrain through the Forge inbox (`VOXPRINT_FORGE_INBOX`, default `~/.voxprint/forge/inbox`).
- Aligned with Model Forge: both train and generate on MOSS-Image-SFT. `voxprint.lora.base_variant` (expected `moss-image-sft`) and `voxprint.lora.base_sha256` (or `base_sha256`) are kept on the LoRA entry. A `moss5b` LoRA with variant `moss-image-base` still loads, with a warning logged and listed under `warnings` in `--json`.
- voxprint-common 0.6.3 (wheel SHA-256 `a18e5760863e34042c6eb16dd25d37d28055b9eb90a460c62407cdc2a09b43e4`) in pyproject, constraints, CI, installers and smoke scripts. Canvas does not use the new `save_image` yet.
- `REPO-MAP.md` describes the repository layout.

## Unchanged

- The content gate.
